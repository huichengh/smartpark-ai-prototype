# 园智汇 ParkOS · 平台功能详细介绍

> 在线演示：<https://smartpark-prototype.app.workbuddy.host/>　｜　账号 `admin` / `Park@2026`
> 版本：2026-11-02　｜　定位：**面向中小产业园区的 AI 经营决策平台（原型）**

---

## 一、这个平台要解决什么

中小园区普遍不缺系统，缺的是**把数据变成决定**的那一步。日常的真实困境是：

- 台账在 Excel、沟通在微信、账目在财务软件，**同一个"出租率"三个部门算出三个数**；
- 有 8 楼空着，但"要不要降租、降到多少、等多久"，靠经验拍；
- 企业快到期了才发现，续租谈判只剩两周，只能被动让步；
- 发现了问题，也开了会，但**没有一条从"发现问题"到"谁在什么时候做完"的链路**。

所以这个平台的设计目标不是"再多一个台账系统"，而是把这条链路做实：

```
看得清（统一口径）→ 算得出（方案推演）→ 判得准（规则+证据）→ 做得完（审批+任务）
```

**边界先说清楚**：这是课程与创业验证用的原型，用模拟数据、单库 SQLite、默认离线规则模式，
**不是可直接生产部署的系统**。所有推演结果都标注"演示数据/推演结果"，不构成收益承诺。

## 四、逐模块功能详解

### 4.1 空间资产（7 个接口）

**解决**：园区到底有多少可出租面积、哪些空着、空多久了。

- 园区 / 楼栋 / 楼层 / 空间四级结构，空间带面积、挂牌价、出租状态、空置起始日
- 楼层看板（`/space/spaces/board/{building_id}`）：状态颜色由后端 `status_legend` 下发，
  前端不自建色表——避免"同一个状态两种颜色"
- 2.5D 数字孪生（`/space/parks/{id}/twin`）：楼栋用等轴测坐标（`map_x/map_y/map_w/map_d/map_h`）绘制
- **口径**：出租率按面积算，不按间数；空置天数从 `vacant_since` 起算，没有该字段就说"缺数据"而不是填 0

### 4.2 招商运营（8 个接口）

**解决**：线索从哪来、卡在哪一步、谁该跟进。

- 线索台账 + 跟进记录 + 阶段推进（`/leasing/leads/{id}/stage`）
- 漏斗分析（`/leasing/funnel`）：按阶段统计数量与转化
- 停滞预警（`/leasing/stagnant`）：超过 N 天无跟进的线索单独列出
- 渠道分析：不同来源的转化对比
- **边界**：只做"线索经营"，不做招商 CRM 的完整客户管理；方案推演在经营决策模块

### 4.3 经营决策工作台（10 个接口）★ 差异化核心

**解决**：8 楼空着怎么办？这家企业会不会走？决定了谁去执行？

三栏布局（左中右 = 待办与风险 / 收益机会 / 推荐行动），四个深度视图：
经营概览、收益沙盘、续租风险、执行任务。

#### （1）经营指标 —— 每个数字都带口径

`GET /operating/metrics` 返回 6 项 KPI，**每项附 `basis`（怎么算的）**：
可出租面积、已出租面积、空置面积、出租率、年化合同租金、平均空置天数。

算不出来的返回 `null + unavailable_reason`，**绝不填 0**——0 会被读成"真的是 0"。

#### （2）招商收益沙盘 —— 三方案可复现

`POST /operating/scenarios/compare`：对单个空置空间生成 A/B/C 三套方案

| 方案 | 含义 |
|---|---|
| A 维持挂牌价 | 价格不动，按当前空置预期等待 |
| B 让价快速成交 | 让价 10% + 1 个月免租，换取提前起租 |
| C 分割改造后出租 | 增加改造投入，换取更高单位租金 |

每个方案输出：实收单价、月租金、租期实收租金、免租让价、招商佣金、装修补贴、
持有成本、空置机会成本、**逐月现金流**、**首次回款月份**、**现金流转正月份**。

关键设计：

- **现金流从今天起算并含空置期**。只算租期内的现金流会让"空置更久"的方案显得回本更快，
  这是实现时真实踩到的错，已修。
- **空置天数由使用者填**，系统不假定"降价一定更快出租"。
- **非法输入直接拒算**：负面积、让价 >50%、免租 ≥ 租期、空置 >365 天等 8 类，
  返回具体原因，不返回兜底数字。
- 配套**敏感性分析**：让价 ±5pp、空置 ±30 天对净贡献的影响。

#### （3）续租风险清单 —— 规则标签，不是概率

`GET /operating/renewal-risks`：对 90 天内到期的合同做规则评分。

| 信号 | 权重 | 证据 |
|---|---|---|
| 30/60/90 天内到期 | 30/20/10 | 到期日、剩余天数 |
| 存在逾期账单 | 25 + 最多 15 | 账单号、欠费额、逾期天数 |
| 近 90 天未闭环高优工单 | 每单 10，上限 20 | 工单号、标题、优先级 |
| 到期前未建立续租接触 | 5 | 最近联系时间 |

- 等级：≥60 高 / 30–59 中 / <30 低；**缺到期日或毫无信号 → "证据不足（UNKNOWN）"**，不是低风险
- 结果固定带 `is_probability: false` 与说明——**没有带标签的历史数据，任何"退租概率"都是编的**
- 允许人工**确认风险**或**解除误报**并留痕（规则必然有误报）

#### （4）执行任务 —— 从建议到验收

`POST /operating/actions` 创建 → 状态机流转 → 关闭。

```
DRAFT → PENDING_APPROVAL → APPROVED → IN_PROGRESS → PENDING_REVIEW → CLOSED
                          ↘ REJECTED        ↘ CANCELLED
```

- 越级迁移被拒，并返回**当前可选状态**
- **双人原则**：审批人不能是创建人（自审直接 403）
- **SLA 与催办**：服务端判定超期（已结束状态不算），`GET /operating/sla-summary` 给出
  超期数、3 天内到期数、超期未催办数；催办只追加时间线，**不改状态**
- 每次状态变化写审计 + `timeline`，可回放

### 4.4 企业服务（8 个接口）

**解决**：一家企业从入驻到成长，园区该提供什么。

- 企业档案（`/enterprise/enterprises/{id}`）：工商信息、联系人、标签、空间、合同、账单、工单聚合
- 政策库与匹配（`/enterprise/policies`、`/policy-matches`）：按行业/规模/资质匹配可申报政策，
  给出申报条件核验与材料清单
- 服务诉求（`/enterprise/service-requests`）：企业侧提需求，园区侧响应
- **隐私边界**：企业画像只用工商与经营类字段，不采集个人敏感信息

### 4.5 合同管理（5 个接口）

**解决**：哪些合同快到期、在险租金多少、续租还是退租。

- 合同台账 + 明细（含免租期、递增规则、付款周期）
- 到期预警（`/contracts/expiring`）与在险年租金
- 续租意向登记（`/renew-intent`）、退租办理（`/terminate`）
- **口径唯一实现**：到期判定收在 `contract_engine`，只统计"生效中/即将到期"，
  已终止合同不计入——这个指标历史上曾有 4 份实现、出现 37 与 39 两个值

### 4.6 财务与账单（7 个接口）

**解决**：钱收没收上来、欠在哪。

- 账单台账、明细、收款记录
- 催缴（`/bills/{id}/dunning`）、缴费登记（`/bills/{id}/pay`）
- 汇总（`/finance/summary`）：应收、实收、欠费、收缴率、账龄分布
- 项目投资视角（`/finance/projects/investment`）：项目预算与支出
- **口径**：收缴率 = 实收 / 应收，按账单口径聚合，不含减免额

### 4.7 项目管理中心（14 个接口）

**解决**：工程类项目进度、成本、风险同时管。

- 项目组合（`/projects/portfolio`）：多项目预算/进度对比
- **WBS + 甘特 + 关键路径**（`/gantt`）：CPM 前推/后推，输出 ES/EF/LS/LF 与总时差
- **挣值分析**（`/evm`）：PV/EV/AC/CPI/SPI/EAC/VAC，带口径说明
- 风险登记册（5×5 概率影响矩阵）、里程碑、问题
- 敏捷视图（Epic/Feature/Story/Sprint/看板），**瀑布式项目请求敏捷数据返回 400 是预期业务行为**，
  前端给产品化提示而非红屏
- **变更影响分析**（`/change-impact`）：见下

#### 变更影响分析（新增）

选一个任务、填顺延天数（审批延误/停工/资源冲突/设计变更），推演：

- 基准工期 → 调整后工期、顺延天数与占比
- 受影响任务清单（区分"完工顺延"与"只是时差变大"/"转为关键任务"）
- 新成为关键路径的任务
- 里程碑推定日期（**已完成的不顺移**——既成事实）
- 成本影响（需提供日成本，不提供就不出数字）

**三条硬约束**：模拟**不改动任何正式计划**（`baseline_untouched: true`）；
要落地必须提交变更申请（`PENDING`）并经 `project:APPROVE` 审批；
创建申请时**服务端重算**，不采信前端传来的天数与金额。

### 4.8 物业运维（13 个接口）

**解决**：报修派给谁、超时了没有、服务质量如何。

- 工单台账 + 明细 + 流转（受理/派单/完成/关闭）
- 按类型统计（`/work-orders/stats/by-type`）：总量、开闭、完成率、超时率、平均处置时长、评分
- 设备台账与巡检记录
- **口径唯一实现**：工单指标收在 `property_engine`，接口与 AI 工具共用

#### 能源 / 安全 / 停车 / 会议室

- **能源**：分项计量与趋势；时段（日间/夜间）与峰谷类型**由 `record_hour` 实时推导**，
  没有小时数据时返回 `null` 并提示"数据不足"，不伪造峰谷比
- **安全**：隐患与事故台账；安全指数 = `100 − 未闭环重大/紧急×8 − 较大×4 − 一般×1.5 − 整改逾期×3`，
  隐患不参与扣分（按条扣会让指数恒为 0）
- **停车**：车位、车辆、访客、道闸记录
- **会议室**：预订与活动，按企业归属隔离

## 五、AI 能力

### 5.1 主 Agent + 12 个子智能体

主 Agent 负责意图识别与路由，12 个子智能体各管一域：

招商AI / 企业画像AI / 空间资产AI / AI项目经理 / 合同AI / 物业AI /
能源AI / 安全AI / 政策AI / 财务AI / **经营优化AI** / 经营分析AI

**经营优化AI** 是这轮新增的第 12 个，把沙盘与风险引擎接进对话：

- 问「某空置楼层怎样出租收益更高？」→ 真调 `compare_leasing_scenarios` 工具，数字来自确定性引擎
- 问「某企业续租有何风险？」→ 调 `list_renewal_risks`，输出规则标签与证据
- 回答额外带 5 个字段：`source_ids`（用到哪些记录）/ `model_version`（口径版本）/
  `assumptions`（假设与声明）/ `data_quality`（数据质量）/ `requires_approval`（是否需人签字）

### 5.2 输出规范

统一八段式：**结论 / 关键数据 / 原因分析 / 建议措施 / 影响范围 / 风险 / 责任部门·角色 / 决策状态**。

### 5.3 权限分级

| 级别 | 含义 | 例子 |
|---|---|---|
| L1 查询 | 只读信息 | 查合同、查工单 |
| L2 建议 | 分析与建议，不落库 | 方案推演、风险清单 |
| L3 动作 | 高影响动作，**必须人工审批** | 调价、改合同、减免账单 |

**AI 不写正式经营数据**：所有写操作必须由持权限的用户显式发起。

## 六、权限与数据隔离

- **RBAC**：15 角色 × 9 动作 × 23 模块 = 207 权限点
- **数据范围 6 种**：GROUP（集团）/ PARK（园区）/ DEPARTMENT / PROJECT / ENTERPRISE（企业）/ SELF
- **fail-closed 原则**：范围算不出来时返回**空集合**，绝不回退到更大范围。
  历史上企业管理员因一个字段未赋值而看到全园区数据，这个教训已写进架构
- **多租户隔离有自动化对抗测试**：换身份去打，验证企业管理员只看得到本企业的
  合同、账单、工单、会议室预定，园区负责人不能跨园区
- **审计**：所有写操作与审批动作留痕，可按对象回放

## 七、工程质量

12 个校验脚本，全部可一条命令跑：

| 脚本 | 查什么 |
|---|---|
| `smoke_test.py` | 端到端 92 项，含三方角色权限隔离 |
| `check_fields.py` | 四维字段校验：属性/构造参数/字典键/路由（141 路径） |
| `check_routes.py` / `check_permissions.py` | 前后端路由与权限键交叉校验 |
| `check_tools.py` | 25 个 Agent 工具逐个真跑，异常即失败 |
| `check_intent.py` / `check_intent_e2e.py` | 意图路由 50 条用例（含"防抢占"） |
| `check_operating.py` | 经营计算 33 条**金标准**（纯函数，可手算） |
| `check_change_impact.py` | 变更影响 30 条金标准（含可手算 CPM 网络） |
| `qa_suite.py` | **对抗测试 61 项**：鉴权、越权、参数边界、数据一致性、任务闭环 |

金标准的意义：财务与工期这类计算，必须"同一组输入必得同一个数"，
任何人都能拿手算结果去核对。

## 八、已知边界（不使用户误解为已具备）

| 事项 | 现状 |
|---|---|
| 生产就绪 | **不是**。SQLite 单库、无迁移工具、无限流与监控，演示账号为固定密码 |
| 统计概率 | **刻意不做**。没有带标签的历史退租/延期样本，只出规则标签 |
| 小时级能耗峰谷 | 缺小时级数据，相关指标返回"数据不足" |
| 企业匹配评分 | 未做。缺带标签的成交数据，做了就是"看起来科学的拍脑袋" |
| 真实客户数据 | 未接入。全部为种子生成的演示数据，接口与页面均带 `data_label` |
| 资源冲突自动识别 | 未做。需要资源日历与技能矩阵，当前由使用者指定顺延天数 |

## 九、五分钟上手的动线

1. `admin` 登录 → **经营决策工作台**，点空置空间的「测算招商方案」，把"预计空置"改成 365 天看数字变化
2. 切到**续租风险**，展开一条看证据链，点「解除误报」
3. 切到**执行任务**，走一遍审批（换 `p1_manager` 批准，验证双人原则）
4. **AI 智能体** 问「某空置楼层怎样出租收益更高？」，看回答底部的来源与审批标记
5. **项目管理中心 → 任一项目 → 变更影响分析**，填 10 天顺延看工期变化
6. 换 `tenant1` 登录，验证菜单与数据同时收窄
