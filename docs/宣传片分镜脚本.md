# 制作须知

## 一、生成参数

- **每个镜头单独生成一条**，模型参数选 **15 秒 / 16:9 / 1080p**。
- 32 条按镜头编号顺序命名（`parkos_s01` … `parkos_s32`），剪辑时按时间码顺序拼接。
- 旁白是中文，建议在剪辑软件里单独配人声，再用 H3 的 `overall_soundscape` 做环境音垫。
  若平台能直接出中文人声，保留原句不动。

## 二、为什么不让模型渲染中文界面

生成模型画中文 UI 文字必然糊。本脚本**全程没有要求出现中文界面文字**，唯一显性文字是
结尾的 `"ParkOS"`（拉丁字母，出错率最低）。「园智汇」三个字、以及所有 KPI 数字，
**一律后期叠加**。

## 三、旁白里带数字的三处

- 镜头 21「收缴率九成三」——旁白用文字写，避免念错
- 镜头 31「一百四十一个接口、六十八张表、两百零七个权限点」——用汉字读更稳
- 其余镜头不含具体数值

> 这三处对应的系统实际值请在**拍摄当天重新核对**（演示库是按固定种子生成的，
> 日期推进后收缴率、工单完成率、安全指数会变）。核对方式见下。

## 四、开拍前的一次自检

```bash
cd backend && python run.py            # 起服务
# 打开 /api/dashboard/summary 取当前收缴率、工单完成率、安全指数
# 打开 /api/operating/renewal-risks 取风险清单条数
```

## 五、避坑提醒

1. **别在同一条里加第二个切点**。本脚本每条只有一个切点（Shot 1 内部），
   H3 在 15 秒内做多次场景切换容易糊。
2. **镜头 10、13、14、24、30 是"界面特写"**，模型最容易把它们画成抽象光效。
   如果出来太抽象，改用真实录屏 + 这条做转场。
3. **人脸一致性**：镜头 03、11、15、20 出现了同一位负责人，统一用
   "the same man in a dark shirt" 这类描述，别换衣服描述。
4. **不要加"电影感""震撼"这类词**。指南里说了，模型对抽象情绪词不敏感，
   写得越具体越可控。

## 六、配套的屏幕录制素材（建议同时录）

宣传片里最出彩的部分建议用**真实录屏**替换或穿插，比生成画面可信得多：

| 素材 | 对应镜头 | 录屏要点 |
|---|---|---|
| 经营决策工作台三栏 | 09–11 | 改参数看数字变，展开证据 |
| 续租风险清单 | 12–14 | 展开一条看证据链 |
| 审批流 | 15–16 | 两个账号交替，展示双人原则 |
| 变更影响推演 | 24 | 选任务 → 推演 → 看受影响清单 |
| AI 问答 | 27–29 | 问「某空置楼层怎样出租收益更高」 |

录屏片段用 `Ref2VA` 模式（把截图作为参考帧）能保持 UI 清晰度。
