# 园智汇 · 演示脚本

分角色演示动线。全程 15–20 分钟，覆盖平台的六条主干能力。
所有页面右上角/页脚均带「演示数据」标注，可随时向观众说明数据为模拟生成。

**启动前提**：后端 `127.0.0.1:8010`、前端 `127.0.0.1:5173` 均已运行。

---

## 第一幕 · 集团管理员视角（账号 `admin` / `Park@2026`）

### 1. 数据驾驶舱 —— 全园一屏

进入即见 18 项核心 KPI。挑三个指标点开悬浮说明（`basis`），
说明**每个数字都能追溯到计算口径**，不是写死的示例值：

- **空间出租率 44.06%** → 已出租面积 237,138 ㎡ ÷ 可租面积 538,227 ㎡
- **租金收缴率 93.19%** → 已到期应收 602,386,673 元中实收 561,376,607 元
- **本月园区总能耗 52,771,077 kWh** → 本月电耗合计，同比 +1.66%

再看**欠费账龄分布**（41,010,066 元分 5 档，365 天以上占 2,606 万）——
这组数据由 `bills.age_bucket` 实时聚合，直接指向催收优先级。

> 讲点：切换右上角「全部园区 / 单园区」，所有 KPI 与图表同步重算，
> 数据范围由后端下推过滤，不是前端筛选。

### 2. 园区数字孪生

2.5D 等轴测楼栋视图。点击楼栋下钻，看楼层出租状态；
楼层看板的颜色由后端 `status_legend` 下发，前端不维护状态色表。

### 3. AI 智能体 —— 平台的大脑

- **问答**：问「本月经营情况如何」→ 返回**八段式**结构：
  结论 / 关键数据 / 原因分析 / 建议措施 / 影响范围 / 风险 / 责任部门 / 决策状态。
  展开证据链，展示结论引用了哪些数据。
- **权限分级**：提问中涉及高影响动作时，回答被标记为 **L3**，
  界面显式阻断「直接执行」，引导至审批中心。这是需求第 37 节的硬性约束。
- **Agent 与工具**：11 个子智能体 + 23 个工具，各带权限级别与职责说明。
- **建议采纳/驳回**：`ai:EDIT` 权限者才可操作，动作写入审计日志。

### 4. 项目管理中心

打开任一项目：WBS 任务、CPM 关键路径（161 天）、EVM 挣值
（CPI 0.998 / EAC 4,609,218.44）。切换到「敏捷」视图——
**瀑布式项目的敏捷视图返回业务提示而非报错**，这是设计上的产品化处理。

### 5. 审批中心

待办列表 → 打开详情：流转轨迹、关联对象、AI 预审意见。
「我的待办」数量来自后端统计，与列表一致。

### 6. 数据中心 / 报表中心 / 日志审计

- **数据中心**：数据资产目录、六维质量评分、字段级血缘（含计算公式与业务规则）。
- **报表中心**：生成园区月报，导出归档。
- **日志审计**：按模块/动作/结果筛选，点开任意一条看**变更前后对照**
  （`before_value` / `after_value`）。登录登出、AI 调用、审批全部留痕。

### 7. 系统管理

角色权限矩阵：15 角色 × 198 权限点，勾选即时保存。
园区模板模块开关（不同园区可启用不同模块组合）。

## 第二幕 · 数据隔离验证（关键环节）

退出，用 `p1_manager` / `Park@2026` 登录（园区负责人）。

**同样的页面，不一样的数据**：

1. 驾驶舱的园区切换器只剩 1 个园区，KPI 全部按该园区重算。
2. 左侧菜单**少了「系统管理」**（该角色无 `system:VIEW`）。
3. 手动在地址栏输入 `/system` → 得到**可读的权限提示页**，
   写明「当前账号（园区负责人）没有 system:VIEW 权限，请联系管理员分配」，
   而非白屏或崩溃。

再用 `tenant1` / `Park@2026` 登录（企业管理员）：

4. 菜单进一步收敛到 9 个模块，财务/合同页面只显示本企业数据。
5. 尝试访问 `/space`（空间资产，园区内部数据）→ 被拒绝。

> 讲点：前端的隐藏只是体验优化，**真正的边界在后端**——
> 每个接口都有 `auth.require(模块, 动作)`，数据范围条件由服务端拼接。

## 第三幕 · 质量保障（如需展示工程严谨性）

```bash
cd backend
python smoke_test.py            # 92 项端到端，含三方角色越权验证
python check_permissions.py     # 前后端权限键一致性，双向校验
python check_enum_mismatch.py   # 枚举列中英错配风险判定
```

说明：项目开发中反复遇到三类编译器发现不了的缺陷——权限键不一致导致页面不可达、
枚举中英错配导致统计静默归零、前端调用不存在的路由导致 404——
因此把它们固化成脚本，退出码非 0 即阻断，可直接接入 CI。

## 演示中可能被问到的问题

**Q：数据是真实的吗？**
全部由 `backend/app/seed/` 的生成器写入数据库（65 张表、约 7 万行），
再由后端实时计算得出。所有响应都带 `data_label: "演示数据"`，界面同步显示角标。

**Q：能换 PostgreSQL 吗？**
能。改 `DATABASE_URL` 环境变量即可，ORM 与查询全部兼容，无代码改动。

**Q：AI 会自己执行操作吗？**
不会。AI 只有 L1 查询与 L2 建议两类能力；L3 高影响动作一律进审批中心，
由具备审批权限的角色人工决策。

**Q：园区之间能看彼此数据吗？**
不能。数据范围在服务端强制下推，跨园区访问返回 403，审计日志留痕。
