# 园智汇 ParkOS · 项目介绍

> 面向中小产业园区的 AI 经营决策平台（原型）
> 在线演示：<https://smartpark-prototype.app.workbuddy.host/>　｜　演示账号 `admin` / `Park@2026`
> 版本：2026-11-02

---

## 一、一句话定位

**把园区"数据齐了但做不出决定"的那一步补上**——从看得清，到算得出、判得准、做得完。

---

## 二、项目简介

中小产业园区的运营，长期卡在"数据齐、判断难"这一步。资产台账在 Excel、企业沟通在微信群、账单在财务软件、工单在物业系统，四个来源各有一套口径，同一个"出租率"三个部门能算出三个数。更关键的是，数据齐了也不等于能决策：8 楼空了三个月，要不要降租、降到多少、还能等多久，仍然靠负责人拍脑袋；企业合同剩两周才被发现到期，续租谈判只能被动让步；会上定的整改事项，散场后没有一条能追到"谁、什么时候、做完了没有"。行业里不缺智慧园区系统，缺的是把数据变成可执行决定的那一层。

园智汇 ParkOS 就是补这一层的平台，按"看得清—算得出—判得准—做得完"组织能力。统一口径：23 个业务页面覆盖资产、招商、合同、财务、项目、物业、能源与安全全链路，六项核心经营指标每一项都附带计算口径说明，算不出来的数据返回"缺失"并说明原因，不用 0 冒充。方案推演：招商收益沙盘针对单个空置空间，用确定性算法测算"维持原价、让价快租、分割改造"三套方案的净经营贡献、逐月现金流、首次回款与现金流转正月份，并给出让价幅度与空置天数的敏感性分析；现金流从当天起算并计入空置期成本，避免"等得越久反而显得越划算"的误判。规则预警：续租风险引擎汇总到期天数、逾期账单、近 90 天未闭环高优工单三类信号，输出可解释的待核实清单，每条结论都能追溯到具体合同、账单与工单，并明确标注这是规则标签而非统计概率。执行闭环：经营建议先进入待审批，由另一名有权限的人员批准后才流转为物业整改、招商跟进或企业回访任务，任务带责任人、截止时间与 SLA，超期自动标红并可催办，验收关闭后回填结果，全过程留痕可回放。

平台同时把项目管理的标准方法做进了系统。项目模块支持 WBS 分解、关键路径前推后推与挣值分析，并提供变更影响分析：选定一个任务、输入顺延天数，即可推演工期变化、受影响任务清单、关键路径迁移、里程碑推定日期与成本影响。这套推演严格区分"模拟"与"落地"——模拟不写入任何正式计划，变更必须提交申请并经审批才能更新基线，金额与天数由服务端重算、不采信前端提交值；已完成的里程碑不随模拟顺移，因为那是既成事实。这对应着交付基线管理、变更控制与 RACI 责任矩阵的要求，是把管理条文变成可点击功能的一次尝试。

项目初期聚焦 5–20 万平方米、尚未部署重型智慧园区系统的中小园区运营公司——这类客户预算有限、数据基础薄弱，也最需要一个"能算清楚"的工具。收费采用分层订阅：基础版覆盖台账与看板，智能经营版包含收益沙盘、续租预警与任务闭环，集团版按园区规模报价。验证分三步走：先用匿名模拟数据确认计算正确性，再选取 1–2 家愿意授权的园区做低风险只读分析试点，对比基准期与试点期的空置天数、到期前接触率、任务关闭时长与建议采纳率，最后再决定是否产品化。

## 四、系统架构

```
┌──────────────────────────────────────────────────────────┐
│  前端（React + TS + ECharts）23 个业务页面                │
│  驾驶舱 / 孪生 / 资产 / 招商 / 经营决策 / 合同 / 财务 …    │
└───────────────────────────┬──────────────────────────────┘
                            │ 141 条 REST 接口
┌───────────────────────────┴──────────────────────────────┐
│  接口层  17 个路由模块 + 统一鉴权（RBAC × 数据范围）        │
├──────────────────────────────────────────────────────────┤
│  AI 编排层  主 Agent → 意图路由 → 12 个子智能体 → 25 个工具 │
├──────────────────────────────────────────────────────────┤
│  计算层  确定性服务（纯函数）                              │
│  operating_engine / renewal_risk_engine / contract_engine  │
│  project_engine(CPM·EVM) / change_impact_engine            │
│  property_engine / safety_engine                           │
├──────────────────────────────────────────────────────────┤
│  数据层  68 张表（SQLAlchemy 2.0）· 审计日志 · 演示数据标记 │
└──────────────────────────────────────────────────────────┘
```

**核心设计取舍**：算与判分离。所有金额、比率、工期由计算层的纯函数产出，
AI 只负责解释与组织表达，不生成任何数值。这是保证"同一组输入必得同一输出"的前提。

### 5.2 核心能力：经营决策闭环

这是平台区别于通用园区管理系统的部分，由四段组成。

**① 统一口径**
6 项核心经营指标（可出租面积、已出租面积、空置面积、出租率、年化合同租金、平均空置天数）
每项附带 `basis` 口径说明；算不出来的返回 `null + unavailable_reason`，不填 0。

**② 方案推演**
对单个空置空间生成三套方案并对比：

| 方案 | 含义 |
|---|---|
| A 维持挂牌价 | 价格不动，按当前空置预期等待 |
| B 让价快速成交 | 让价 + 免租，换取提前起租 |
| C 分割改造后出租 | 增加改造投入，换取更高单位租金 |

输出实收单价、租期租金、免租让价、佣金、装修补贴、持有成本、空置机会成本、
逐月现金流、首次回款月份、现金流转正月份，以及让价 ±5pp、空置 ±30 天的敏感性分析。
8 类非法输入（负面积、让价 >50%、免租 ≥ 租期、空置 >365 天等）直接拒算并说明原因。

**③ 风险判定**
续租风险引擎汇总四类信号（到期天数、逾期账单、未闭环高优工单、续租接触），
每条带来源与证据字段；等级高/中/低/证据不足；结果固定标注"规则标签，非统计概率"；
支持人工确认与解除误报并留痕。

**④ 执行闭环**
任务状态机：`DRAFT → PENDING_APPROVAL → APPROVED → IN_PROGRESS → PENDING_REVIEW → CLOSED`，
另有 `REJECTED / CANCELLED` 分支。越级迁移被拒并返回当前可选状态；审批人不能是创建人；
超期由服务端判定并标红，可催办（只记时间线不改状态）；每次变化写审计与时间线，可回放。

### 5.3 项目变更影响分析

选择受影响任务与顺延天数（审批延误 / 停工 / 资源冲突 / 设计变更），推演：

- 基准工期 → 调整后工期、顺延天数与占比
- 受影响任务清单（区分完工顺延 / 时差变大 / 转为关键任务）
- 新成为关键路径的任务、里程碑推定日期（已完成的不顺移）
- 成本影响（须提供日成本，不提供则不出数字）

硬约束：模拟不写入任何正式计划；落地须提交变更申请并经审批；数值由服务端重算。

## 六、权限与数据安全

- **RBAC × 数据范围双控**：15 角色 × 9 动作 × 23 模块 = 207 权限点；5 种数据范围
- **fail-closed**：范围无法确定时返回空集合，绝不放大可见范围
- **多租户隔离**：企业管理员只能看到本企业的合同、账单、工单、会议室预定；
  园区负责人不能跨园区访问——由对抗测试逐条验证
- **审计**：所有写操作与审批动作留痕，可按对象与时间回放

## 八、开发方式与 AI 使用

本项目全程采用 WorkBuddy（AI 编程 Agent）配合 DeepSeek 大模型辅助开发，覆盖需求拆解、
架构设计、代码生成、测试用例编写与文档撰写。

开发周期约 47 天，产出约 3.8 万行代码与 7 篇技术文档，维护 137 个受版本控制的文件。

AI 在本项目中的角色是开发工具，不是运行时依赖：系统运行阶段不调用任何大模型，
全部结论由数据库查询与后端确定性函数计算得出。

这样设计的目的是保证结论可复现——同一组输入必得同一输出，评审可随时用手算核对；
同时演示过程不依赖网络，断网仍可完整运行。

系统预留了大模型接入位（`AGENT_MODE` 配置项），后续如接入，模型仅负责解释工具返回结果，
不参与任何数值计算。

## 九、应用场景与商业路径

**目标客户**：5–20 万平方米、尚未部署重型智慧园区系统、依赖 Excel 与微信管理的中小园区运营公司。
**次级客户**：需要集团层面做多园区资产经营分析的地方国资运营平台。

**收费模式**（待验证的假设，非已成交报价）：基础版订阅、智能经营版增值、集团版按规模报价。

**验证路径**：
1. 匿名模拟数据验证计算正确性（已完成）；
2. 选 1–2 家愿意授权的园区做低风险只读分析试点；
3. 对比基准期与试点期的空置天数、到期前接触率、任务关闭时长、建议采纳率；
4. 依据结果决定是否产品化。

## 十、已知边界

| 事项 | 现状与原因 |
|---|---|
| 生产就绪 | **不是**。SQLite 单库、无迁移工具、无限流与监控，演示账号为固定密码 |
| 统计概率 | **刻意不做**。没有带标签的历史退租/延期样本，只出规则标签 |
| 小时级能耗峰谷 | 缺小时级数据，相关指标返回"数据不足"，不伪造节能率 |
| 企业匹配评分 | 未做。缺带标签的成交数据，做了就是"看起来科学的拍脑袋" |
| 真实客户数据 | 未接入。全部为种子生成的演示数据，接口与页面均带 `data_label` |
| 大模型运行时调用 | 未接入。当前为规则推理模式，结果可离线复现 |
| 资源冲突自动识别 | 未做。需资源日历与技能矩阵，现由使用者指定顺延天数 |

## 十一、演示动线（约 8 分钟）

1. `admin` 登录 → **经营决策工作台**，点空置空间「测算招商方案」，把预计空置改成 365 天看数字变化
2. 切 **续租风险**，展开一条看证据链，点「解除误报」
3. 切 **执行任务**，换 `p1_manager` 审批，验证双人原则与超期催办
4. **AI 智能体** 问「某空置楼层怎样出租收益更高？」，看回答底部的来源与审批标记
5. **项目管理中心 → 任一项目 → 变更影响分析**，填 10 天顺延看工期变化
6. 换 `tenant1` 登录，验证菜单与数据同时收窄
