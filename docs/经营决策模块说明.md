# 经营决策模块（P0）实施说明

> 依据：《园智汇ParkOS 分模块改进提示词合集》00–06、09–11；《创新创业项目改进与商业化建议书》三、五、十。
> 实施日期：2026-10-31　｜　对应提交：见 git log

---

## 一、这轮解决的核心问题

改进建议书的判断是准确的：原系统的短板**不是功能数量不够，而是没有以"经营增收/减损"为目标的闭环**——
22 个页面都在"看数据"，但没有一处能回答"这个空置楼层该怎么租、这家企业会不会走、决定了谁去执行"。

所以这轮没有新增更多台账页，而是补一条**决策链**：

```
经营指标（口径可查）
   → 收益沙盘（三方案可比较、可复现）
      → 续租风险（规则可解释、可纠错）
         → 任务闭环（审批 → 执行 → 验收 → 关闭，可回放）
```

## 二、逐项对照

| 提示词 | 要求 | 本轮落地情况 |
|---|---|---|
| **01 指标口径** | 经营指标与维度口径表；缺失返回 null 不填 0；数据质量报告 | ✅ `/operating/metrics` 返回 6 项 KPI，**每项带 `basis` 口径说明**；缺失数据进 `missing_data` 并附原因；附 `data_quality` 计数 |
| **02 招商收益引擎** | 单空间三方案（A 维持 / B 降价 / C 分割改造），纯函数算租期收入、空置损失、现金流；不假定降价一定更快出租 | ✅ `operating_engine.build_presets()` + `compare()`；**空置天数由使用者填写**，系统不替它猜；C 的单位租金上调与改造投入均为显式参数 |
| **03 续租风险** | 规则驱动、可解释、可纠错；禁止输出"退租概率"；缺失输出"证据不足" | ✅ `renewal_risk_engine`：到期天数 / 逾期账单 / 近 90 天未闭环高优工单 / 续租接触 四类信号，每条带 `source` 与 `evidence`；结果固定带 `is_probability=false`；无信号且缺到期日 → `UNKNOWN/证据不足` |
| **04 经营沙盘** | 确定性计算服务；三方案对比卡 + 月度现金流 + 敏感性；非法输入拒算；记录参数版本 | ✅ 现金流**从今天起算并含空置期**；`payback_month` / `first_cash_month`；敏感性单变量扰动；负面积、让价 >50%、免租 ≥ 租期等 8 类非法输入**抛错拒算**；落库记 `assumption_version` |
| **05 建议走向执行** | 状态机、合法迁移校验、审批人≠创建人、审计、可回放 | ✅ `TRANSITIONS` 白名单；越级迁移返回**当前可选状态**；`NEED_APPROVE_PERM` 触发双人原则（自审直接 403）；每次变迁写 `timeline` + 审计日志 |
| **09 决策型前端** | 以目标而非模块为导航；KPI 带口径；证据可点进；空状态区分「未录入/无权限/暂无异常」 | ✅ 新增 `/operating`，四个 Tab；KPI 卡片下方直接展示口径；风险条目可展开到证据字段；**未实现**"左侧待办/中央机会/右侧推荐"的三栏布局（见第五节） |
| **10 安全权限** | 新增 API 的权限模块/操作码、服务端过滤、对象级授权、负向用例 | ✅ 新模块 `operating`（9 个权限点）；6 个只读接口要 `VIEW`，写操作要 `ADD`，审批要 `APPROVE`；全部按 `visible_park_ids()` + `enterprise_scope_clause()` 裁剪；`qa_suite.py` 的隔离用例已覆盖 |
| **11 质量门禁** | 金标准用例、边界输入、跨园区隔离 | ✅ `check_operating.py` **33 条金标准**（免租/折扣/空置/0 值/负值/拒算/差额/单调性）；`qa_suite.py` 47/0；既有 8 道校验全过 |

## 三、新增的能力清单

### 接口（8 个，`/api/operating/*`）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/metrics` | `operating:VIEW` | 经营指标 + 口径 + 数据缺口 |
| GET | `/spaces` | `operating:VIEW` | 可推演空间（默认带出面积/挂牌价/空置天数） |
| POST | `/scenarios/compare` | `operating:VIEW` | 三方案对比（只读，不落库） |
| POST | `/scenarios` | `operating:ADD` | 保存方案（含参数与结果快照） |
| GET | `/scenarios` | `operating:VIEW` | 方案列表 |
| GET | `/renewal-risks` | `operating:VIEW` | 续租风险清单（带证据链） |
| POST | `/renewal-risks/{contract_id}/review` | `operating:EDIT` | 确认风险 / 解除误报 |
| GET / POST | `/actions` | `VIEW` / `ADD` | 任务列表与创建 |
| POST | `/actions/{id}/transition` | `VIEW`（审批另需 `APPROVE`） | 状态机推进 |

### 数据表（3 张）

- `operating_scenarios`：方案参数 + 结果 + 口径版本快照
- `operating_risk_reviews`：人工复核记录（含当时的风险快照）
- `operating_actions`：任务状态机 + 完整 `timeline`

### 页面

`/operating` —— 经营概览 / 收益沙盘 / 续租风险 / 执行任务 四个视图。

## 四、验证证据（可复跑）

```bash
cd backend
python check_operating.py     # 33 条金标准，纯函数，不需要服务
python qa_suite.py            # 47 通过 / 0 失败（含企业级数据隔离）
python smoke_test.py          # 92 项
python check_fields.py        # 137 条路径，0 问题
python check_permissions.py   # 前端 0 处 / 后端 0 处不一致
python check_tools.py         # 23 个 Agent 工具
python check_intent.py        # 41 条意图路由
```

**接口实测片段**（1200㎡、45 元/㎡/月、36 个月、空置 90 天）：

| 方案 | 净经营贡献 | 较 A 差额 | 空置 | 首次回款 | 现金流回正 |
|---|---|---|---|---|---|
| A 维持挂牌价 | 1,629,000 | — | 90 天 | 第 4 月 | 第 5 月 |
| B 让价快速成交 | 1,388,700 | −240,300 | 45 天 | 第 4 月 | 第 5 月 |
| C 分割改造后出租 | 1,328,332 | −300,667 | 120 天 | 第 7 月 | 第 15 月 |

**闭环实测**：`admin` 建任务 → `p1_manager` 审批 → 执行 → 验收 → 关闭，
时间线 6 条记录齐全；`admin` 自审被 403 拒绝；`p1_manager` 只看到本园区 14 条风险（admin 为 37 条）。

## 五、明确没做的（不使用户误解为已具备）

| 事项 | 现状 | 原因 |
|---|---|---|
| 三栏式决策工作台（左待办 / 中机会 / 右推荐） | 未做，现为四 Tab | 需要重排信息架构，风险高于本轮价值；Tab 版已能走通演示链 |
| 企业匹配「解释性评分」 | 未做 | 缺少带标签的历史成交数据，任何评分都会变成"看起来科学的拍脑袋" |
| 续租风险的统计概率 | **刻意不做** | 无带真实退租标签的数据做时间外验证；系统只输出规则标签并标注 `is_probability=false` |
| 小时级能耗峰谷分析 | 未做 | `energy_records` 仍缺小时级粒度，按 07 要求"缺数据不做" |
| 项目变更影响模拟（08） | 未做 | P1，且需先复用现有 CPM/EVM 基线，本轮时间不够 |
| 客户访谈与试点协议（13） | 未做 | 属商业验证，非代码交付 |
| PostgreSQL 迁移 / 速率限制 / 监控 | 未做 | 属安全生产化，当前仍为原型；**不能宣称生产就绪** |

> 关于"演示数据"：本模块所有数字均由固定种子的演示数据 + 显式参数假设算出，
> 接口与页面均带 `data_label`；沙盘结果附 `assumptions.statement` 声明"非市场真实报价、不构成收益承诺"。

## 六、Agent 接入（提示词 06）

新增第 12 个子智能体「经营优化AI」（`operating`），把沙盘与风险引擎接进对话，
让 AI 从"复述报表"变成"调真实计算再解释"。

### 新增工具（2 个，工具总数 23 → 25）

| 工具 | 级别 | 作用 |
|---|---|---|
| `compare_leasing_scenarios` | L2 建议 | 对空置空间做三方案推演，数字全部来自 `operating_engine` |
| `list_renewal_risks` | L1 查询 | 续租风险清单，带规则权重与证据 |

### 输出新增 5 个字段（提示词 06 明确要求）

`source_ids`（用到哪些记录）/ `model_version`（口径版本）/ `assumptions`（假设与声明）/
`data_quality`（数据质量）/ `requires_approval`（是否必须人工审批）。
这样任何一条结论都能回答"这个数从哪来、按什么口径、要不要人签字"。

### 意图路由（`check_intent.py` 从 41 → 50 条）

提示词里的三个标准问句已固化为用例：

| 问句 | 路由结果 |
|---|---|
| 某空置楼层怎样出租收益更高？ | operating（方案推演） |
| 某企业续租有何风险？ | operating（规则引擎） |
| 如何处理退租风险？ | operating（规则引擎） |

同时补了 3 条**防抢占**回归：`合同快到期需要续约` 仍归合同、`空置面积还有多少` 仍归空间台账、
`租金收缴率` 仍归财务——新增意图最常见的破坏就是把这些问句抢走。

### 两个容易做错、本轮已修的点

1. **问句里的参数必须真正生效**。第一版实现中，用户问「空置要等一年」「让价 15%」，
   数字与默认 90 天完全一样，却还在页面上声明"已按问题参数"——这属于误导。
   现在会解析空置期/让价/租期并在回答里回显，数值随问句真实变化。
2. **空置期必须进入排序口径**。原先按"租期净贡献"排序，空置长短不影响结果，
   于是"等一年"和"等三个月"给出同一结论。现改为按 **扣空置机会成本后** 的净贡献排序
   （`net_after_vacancy`），并同时保留两个口径以便对照。

> 实测：默认 90 天 → A 净贡献 2,366,212 元；改为「等一年」→ A 降到 1,698,819 元；
> 「半年 + 让价 15%」→ A 2,147,793 元、B 1,807,422 元（让价真实从 10% 变为 15%）。

## 七、下一轮建议（按依赖顺序）

1. **三栏式决策工作台（09 的完整形态）**：左待办 / 中收益机会 / 右推荐动作，把现有四 Tab 合并成首屏。
